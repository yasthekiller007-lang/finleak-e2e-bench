# Phase 7 implementation architecture

Starting tree: main `4a0d2520d4713355cec8b143f233aa61e5e655cc`. This is the operational hardening of the existing pipeline, authorized by [execution decisions](phase7-implementation-decisions.md) under the unchanged [audit](phase7-pilot-readiness-spec.md). Implementation is in progress; component descriptions below are checkpoint targets until tests and final traceability establish coverage. No deployed runtime is claimed.

## Boundaries

Next.js remains the confidential OIDC browser application and protected server proxy. FastAPI independently verifies JWTs and current PostgreSQL membership. PostgreSQL 17 stores the same immutable financial/proof/recovery truth. Exact originals remain behind ObjectStorage. No operation silently evaluates, approves facts/findings/recovery, generates/repairs/reviews/succeeds proofs, or reprocesses extraction. No new financial ledger or monetary authority is introduced.

## Original-source lifecycle

Exact uploaded bytes are private and untrusted until a bounded private scan validates their stored hash/size and returns clean. Scanner failure/timeout remains closed. Controlled release is operational and auditable. Normal content/process/proof/recovery source reads must not bypass the release boundary. Scanner reads use a private raw storage path; no public test/scan bypass is introduced. Referenced historical bytes and existing financial/proof/recovery snapshots remain immutable.

## Transactions and concurrency

Reuse existing tenant organization locks and current membership fencing. Shared intake/processing admission must use PostgreSQL across workers, with bounded lifetimes and explicit failure. Scan/release and operator actions must lock/recheck their tenant identities and record who/when/what. Existing Phase 4–6 financial transactions, budgets, canonicalization, currentness and commit provenance remain authoritative.

## Runtime qualification

Readiness means configured and safe to accept traffic; liveness means only that the process responds. Production fails closed on unsafe/incomplete configuration, schema/PG/privilege mismatch and critical original-store/scanner contracts. Real-time IdP availability is tracked separately to avoid readiness flapping. S3 permissions, encryption/version preservation, real issuer behavior, actual alerts, managed PITR and deployed restore remain external qualification obligations.

Engineering targets are RPO ≤1 hour and RTO ≤8 staffed hours. A logical restore cannot invent missing original commit timestamps. Captured Phase 6 publication metadata must reconcile; uncaptured original transactions remain unresolved unless authentic provenance is independently preserved.

## Delivery

Every major valid milestone is committed and pushed; all existing CI checks remain. One final PR receives complete push and PR CI on the same final head. No automatic merge, deployment, purchases or customer intake. Gate status and pilot NO-GO remain explicit while required external evidence is absent.

## Checkpoint B2 implementation

## Checkpoint C1 implementation

`modules/s3_storage.py` uses the locked boto3 SDK behind ObjectStorage. Exact original bytes are captured under an actual size bound, checksummed and published with `IfNoneMatch=*`, server-side AES256 encryption and a required version ID. Canonical tenant/document/source keys are mandatory. Reads are bounded and source verification continues to hash actual bytes against PostgreSQL metadata; metadata alone never proves integrity. Remote errors omit provider messages/URLs/content. Single-attempt SDK calls use connect/read timeouts; source read/write deadlines also reject over-budget work. Socket timeouts remain the upper bound for an individual blocked I/O, so elapsed qualification is measured separately.

Readiness requires version preservation and AES256 encryption. Default `public-block` requires all four S3 public-block controls. An explicitly selected compatible `no-policy` profile requires owner-only ACLs and complete absence of a bucket policy; it does not trust a provider’s IsPublic flag. Provider IAM, anonymous access and persistence still require independent real-provider evidence. No presigned URL, public bucket or final provider is selected.

Shared Local/S3 fixture conformance tests cover byte/size/hash, oversize cleanup and simultaneous conditional publication. SDK shape tests verify real modeled conditional/encryption/checksum parameters. CI builds the official CVE-fixed MinIO source at `9e49d5e7a648f00e26f2246f4dc28e6b07f8c84a` and exercises six isolated synthetic service cases including anonymous denial and preserved versions. Its documented dummy ACL omits owner identity, so the production private-readiness profile correctly rejects it. The integration asserts that rejection and separately verifies real version/encryption/byte/anonymous-access behavior; it does not qualify MinIO for deployment or weaken private readiness. The test service receives no runner/application secrets and is excluded from production images. This cannot graduate real cloud storage privacy/PITR evidence.

## Checkpoint C2 implementation

`modules/source_preservation.py` wraps application storage. Only that worker’s successfully published new upload has a single-use compensation capability. Successful registration consumes it; ordinary deletion and another worker’s arbitrary deletion are denied. Registration and compensation use the same PostgreSQL advisory transaction lock for the canonical key. Compensation rechecks committed Document metadata in a fresh transaction; registered originals and uncertain database outcomes preserve bytes. Denied cleanup remains an explicit safe error and an orphan-reconciliation obligation. Real PostgreSQL race tests cover committed versus rolled-back registration while compensation waits.

`operations/source_inventory.py` is an operator-only read-only command with a repeatable-read PostgreSQL snapshot, document/work/cumulative-byte bounds and actual-byte verification. Missing/corrupt originals fail reconciliation. A resource bound returns INCOMPLETE, never a successful partial inventory. Output contains only internal IDs, expected sizes/hashes and statuses, with a domain-separated inventory digest; no filenames, content or financial amounts. This is operational restore evidence, not another authoritative source or financial export. Actual cloud version/lifecycle/IAM preservation and restored-provider reconciliation remain external evidence pending.

Production IAM must deny ordinary source/version deletion; denied orphan cleanup must remain explicit for protected operators. No financial result, proof identity or recovery event is recalculated by storage operations. Scan/release gating remains checkpoint E2 work; this intermediate checkpoint does not authorize pilot intake.

## Checkpoint E1a implementation

The backend rejects unapproved Host values and the runtime ignores forwarded headers by default. Production origins remain HTTPS-only; API/DB/scanner/store stay private under the deployment contract. JSON receipt is bounded to 1 MiB actual bytes and a 90-second receipt budget; existing proof/recovery JSON guards and multipart original limits remain. JSON responses above 10 MiB return an explicit resource error before any partial body is sent. This is a presentation/operational limit, not a truncated authoritative total. Original downloads retain their separately verified source-byte bound. Protected APIs, health and errors are no-store, with safe request IDs.

Backend and frontend add nosniff, frame denial, no-referrer, object/base/frame CSP and disabled unused browser permissions. Document sandbox headers are preserved. The minimal CSP avoids breaking normal OAuth or introducing unsafe script-policy assumptions; stricter script CSP remains later qualification work. Frontend HSTS uses a one-day host-only profile, with no preload/includeSubDomains commitment; actual HTTPS ingress/owned-domain verification remains pending. Session cookies explicitly retain HttpOnly, SameSite=Lax and Secure for HTTPS. Ambiguous public origin paths/query/fragments are rejected. Shared upload/process admission is the next E1b checkpoint; this intermediate checkpoint does not claim that guarantee.

## Checkpoint E1b implementation

Migration 0008 adds immutable versioned intake profiles and admission attempts, without financial columns. PostgreSQL session-level advisory slots remain held on a dedicated connection through upload receipt or synchronous processing, including intermediate business commits. Initial `pilot-intake/1` defaults are two uploads and one processing operation per tenant, and ten upload/process attempts per actor across all tenants per rolling minute. These are engineering defaults, subject to measured qualification; they cannot truncate financial results. Workers using different configuration under the same version fail explicitly rather than multiplying capacity. The database checks current membership/availability, held tenant/operation slot, server-clock counters and immutable history. App has insert/read access only to these records; no update/delete/truncate privilege.

Admission precedes multipart parsing; authentication completes before admission. Its short authorization transaction commits before acquiring another connection; admission independently rechecks current authority. Multipart receipt is bounded by actual bytes and 90 seconds. Failed operations retain their committed attempt and release all locks; failed release invalidates the physical connection. The tenant session fence makes offboarding wait for actual work, not merely the admission commit. User revocation/deactivation remains transaction-fenced: processing claims and completion recheck membership separately. A user session lock is deliberately not held on the admission connection, because a waiting exclusive revocation could deadlock a business transaction on another connection. Revocation between processing commits blocks publication under the revoked authority; it does not permit an old request to restore access. Explicit 429/503 responses include Retry-After. No queue, worker-local quota, financial side effect or automatic reprocessing is introduced.

Real PostgreSQL tests cover independent worker pools, both operation capacities, atomic actor quota, cross-tenant quota, failed work, configuration mismatch, stale roles, offboarding and direct database bypass/backdating/history edits. Current-head migration comparison is complete; historical checkpoint comparisons exclude only later operational tables. Transactional API fixtures explicitly bind admission to their externally owned transaction and clear recovery SQL budgets only after request teardown, matching runtime pool checkin; no runtime header/environment enables an admission bypass. Local tests do not substitute for PostgreSQL CI or measured pilot load. Private scanner/release and parser containment remain the following checkpoint.

## Checkpoint E2a transport

`modules/scanner.py` implements provider-neutral verdicts and bounded ClamD INSTREAM over a private local Unix socket. TCP is restricted to literal IPv4 loopback for engineering protocol fixtures; production construction requires the local socket. No DNS/public scanner/SaaS path is accepted. The adapter sends exact byte chunks without source transformation, counts actual bytes, bounds replies to 256 bytes, applies socket deadlines and retains only sanitized engine/database identifiers. Clean requires the exact OK response; infection, heuristics, malformed/unknown replies, missing scanner, old/unqualified versions and timeout never become clean. The versioned initial engine profile admits supported 1.4 LTS ≥1.4.6 or 1.5 ≥1.5.4, following the [official security release](https://blog.clamav.net/2026/08/clamav-154-and-146-security-patch.html); later engine/profile changes require advisory review. Signature update/freshness, private permissions and actual deployment remain qualification obligations. Clean is not a guarantee of threat absence.

Tests exercise real socket/protocol I/O, exact chunks, diagnostic exclusion, bounds, outage, timeout and version rejection. Local Work forbids Unix sockets, so that one test is explicitly unavailable locally and mandatory in GitHub CI; loopback protocol tests pass locally. These are protocol fixtures, not an actual malware-engine result. Real ClamAV/EICAR integration and persistent scan/release gating are subsequent E2 checkpoints; this transport-only checkpoint does not enable ordinary unscanned originals or claim the gate is finished.

## Checkpoint E2b persistent availability

Migration 0009 introduces append-only scan, release and request records bound to stable tenant/Document/hash/size. No financial column or source-identity replacement is introduced. Scan sequence is serialized under current user/organization/Document fences. The latest explicit verdict governs availability; a later failed scan blocks a previous release while preserving every old record. Release pins the current clean scan and rehashes actual private bytes. Both exact request retries and simultaneous semantic releases preserve content identity; request aliases bind every key to its original payload. Database guards check current roles/tenant/source, sequence, supported scanner profile/version, clean-byte equality, pinned releases, attributed principals, server times and immutable history. Scanned original hash/size/key cannot be rebound.

`source_gate.py` exposes explicit status, scan and release operations. Analyst/owner/admin may request scan; owner/admin release; viewers read authorized status. The separate restricted scanner database principal appends verdicts; the ordinary app principal cannot forge them. The restricted scanner cannot grant release or write financial authority. Production requires verified scanner DB TLS plus the private Unix socket, with exact schema and enabled guards. Scan/release share processing admission, so scanner work cannot multiply that tenant capacity. No default clean state or production bypass exists.

`ReleasedObjectStorage` wraps preserved application storage for all normal consumers. It holds a Document read fence through the stream and requires current released state; unavailable gate/database fails closed. Private raw access is limited to explicit scanner/release and protected inventory/restore tooling. Content/process endpoints also check before download or creating an extraction attempt. Proof/recovery byte verification retains actual hash/size checks; quarantine is an availability overlay and never mutates an old canonical manifest, financial amount, evaluation or recovery record. No action triggers an upstream workflow.

Tests cover unscanned and clean-pending state, explicit owner release, all nonclean verdicts, actual hash mismatch, release-time tamper, request conflicts/aliases, newer failed scan, stale clean release, cross-tenant/viewer denial, append-only audit and source identity. Real PostgreSQL race tests cover simultaneous release identity/aliases and a held original read versus failed rescan. Restricted-role tests distinguish app, scanner and financial authority. Current-head full metadata comparison and empty reverse/re-upgrade coexist with populated-history downgrade refusal. Existing financial/proof/recovery fixtures explicitly scan through a test-only adapter and release through a separate seeded owner; tested analyst/viewer roles and monetary assertions remain unchanged. These tests are engineering evidence, never an actual malware-engine or deployment claim. Real engine qualification, upload-time parser confinement and vulnerability triage remain next.

## Checkpoint E2c — protected upload and parser children

Both upload structure validation and extraction parse untrusted PDF/CSV/XLSX only in disposable Linux children. `linux-parser/1` requires Landlock ABI ≥3 and libseccomp: exact private source plus application code, Python runtime and shared-library directories are read-only; other original/data/config/credential directories are absent from the rules. File creation, write, truncation and rename are denied. A native-architecture seccomp default-deny profile admits inert Python parsing syscalls, excluding network/socket, execution, fork/clone, privileged operations, io_uring and filesystem mutations. No-new-privileges prevents privilege acquisition. Only stdin/result/discarded stderr descriptors survive launch; credentials are not forwarded. CPU, address-space, output and parent time limits remain. A bounded real child installation/read/write/network probe joins production readiness; unavailable protection blocks upload/processing instead of using an unprotected fallback. The backend runtime installs libseccomp; CI exercises the child under non-root/read-only/dropped-capability controls.

Exact private upload bytes are copied with size bounds and restored stream position; validation never transforms the original or launches extraction/evaluation/proof/recovery. Passive PDF qualification rejects encrypted/corrupt originals, active actions/scripts, external actions, XFA, attachments and rich media, with bounded graph traversal. Scanned passive PDFs remain admissible but extraction still reports needs_ocr; OCR is not added. XLSX rejects external relationships/links and ActiveX, preserving XML entity, archive/member/size/macro controls. Formulas are never executed; existing extraction preserves its explicit ignored-formula warning. Unsupported originals fail before source registration/download, with safe generic errors. This changes operational intake safety, not approved financial meaning. `safe-parser/2` records the new parser profile in new candidate runs; old extraction, evaluation and canonical proof snapshots remain unchanged.

Actual Linux child tests attempt other-document/secret/proc reads, source writes/truncation, creation/symlink/chmod, network sockets, exec and fork, and require denial while the exact allowed source remains readable. Real upload and extraction children exercise all three formats. Local Work lacks Landlock and reports this explicitly: these kernel tests skip locally, but **fail instead of skipping under GitHub Actions**. No simulated kernel result qualifies containment. Pure structural, arithmetic, financial and guard regressions remain separate. Existing malformed/encrypted API tests now assert rejection before any Document/ExtractionRun; original bytes and monetary assertions are preserved. A valid synthetic PDF replaces the historical header-only upload fixture.
