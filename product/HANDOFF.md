## Implemented

- Safe direct-text PDF / UTF-8 CSV / XLSX parsing with source locations and inert spreadsheet handling.
- Provider-agnostic explicit-label extraction with independent normalization, validation and evidence.
- Nullable contract/amendment/invoice candidates, exact Decimal strings and NUMERIC(20,6), conservative dates/currencies; no invented facts.
- Tenant-scoped audited ExtractionRun / ExtractedField records; migration 0003 with data-loss guards.
- Serialized idempotent processing, reprocessing history, bounded worker execution, configurable limits and stale-lease recovery on subsequent requests.
- Protected process/reprocess/latest/history/version APIs and a document detail/evidence review UI.
- 16-document synthetic golden benchmark and security, parsing, concurrency and migration regression tests.

Phase 3 extracted data remains candidate data. Phase 4 adds a separate stable `ReviewedFinancialSource` identity and append-only, source-backed reviewed revisions; processing or confidence never constitutes approval. Existing Contract/Invoice required columns are not populated from incomplete candidates. Owner/admin approval authorizes financial facts; analysts prepare reviews and viewers read only.

- Approved scoped terms, governing-packet attestations, references and one-master associations preserve source hashes, original machine values, reviewed values, uncertainty, actor/time and extraction lineage.
- The pure deterministic compiler supports fixed unit price, complete fixed cycle/event fee, and explicit unconditional percentage discount only. Combined price/discount rules create one coherent scope finding.
- Tenant-serialized PostgreSQL evaluation pins and rechecks revisions and evidence at commit. Concurrent material changes cannot create mixed findings; stale requests fail safely and duplicate evaluations share one semantic result.
- Migration 0004 adds immutable evaluations, normalized tenant-safe evidence, review/finding decisions and trigger-generated audit history. Historical inputs and monetary outputs cannot be manually edited; new evidence requires new revisions/evaluations.
- Protected review, compile, evaluation, history, audit and summary APIs connect to the enterprise review UI, finding register, calculation/evidence detail and dashboard. Blocked amounts remain unknown; potential leakage is not recovered cash.

Phase 5 consumes immutable Phase 4 evaluations and their pinned historical revisions. It creates no financial evaluation, calculation, aggregate finding or replacement financial policy.

- Immutable proof family/content/envelope/binding identities; canonical exact JSON, domain-separated SHA-256 manifest and full frozen-snapshot digest; automatic C01–C10 completeness.
- Actual bounded SHA-256 source reads, verified byte capture for downloads, source-unavailable/mismatch overlays and audited quarantine transitions. Generic original downloads also verify bytes.
- PostgreSQL tenant/membership/revision fencing, shared advisory-operation slots, actor rolling quota, semantic/request idempotency and atomic trigger-origin financial audit reuse.
- Append-only inert annotations, analyst review/disclosure proposals, owner/admin final review/disclosure/export and explicit same-scope successors. Financial decisions remain Phase 4 actions.
- Separate owner-approved disclosure views and private canonical JSON artifacts. Recursive masks cover duplicate/partial values, keys, export metadata and original evidence digests; limited verification is explicit. Canonical internal proof remains unchanged.
- Internal proof summary, exact contractual/billing/calculation/provenance detail, source verification, revision/history/annotation/review/disclosure/export/successor controls and paginated bindings/history. Viewers read issued proofs but cannot generate.
- Migration 0005 adds seven tenant-scoped immutable proof tables, composite evidence/audit FKs, origin/authorization/integrity triggers and historical-source deletion guards. Populated proof/audit downgrade is refused.

Phase 6 adds one stable case per immutable FinancialEvaluation, stable economic instruments and append-only reviewed proposals/evidence/records/aliases/requests/commit provenance. Migration 0006 applies composite tenant FKs, immutable financial history, role/predecessor/pin/budget guards and trusted FinancialAudit triggers. R01–R10 govern cash, applied credit and supported unpaid-liability reductions; issuance/claims/vendor positions/forecasts never create recovery automatically. Tax-exclusive principal, gross performance, deductions, net bank cash, pending credits, direct costs and operational workflow remain separate. Manual protected upload is reused; legacy LeakageCase.recovered_amount is not authoritative.

The internal `/recovery-ledger` experience supports explicit preparation/approval, workflow/lifecycle/history and bounded reproducible reporting. It never secretly evaluates/finds/decides/generates/repairs/reviews proofs, creates a ProofSuccessor or reprocesses extraction. No Recovery Ledger export, PDF, vendor portal/sending, ERP/GL posting, FX, bundled settlement allocation, forecast/annualized/avoided monetary authority or gain-share is introduced.

## Startup

Prerequisites: Python 3.12 / uv 0.12.19, Node 24 / npm, PostgreSQL 17. Versions are locked. Configure only environment settings or ignored local files; never commit credentials.

Backend requires `FLA_DATABASE_URL` (postgresql+psycopg), `FLA_ENVIRONMENT`, `FLA_STORAGE_ROOT`, `OIDC_ISSUER_URL`, `OIDC_AUDIENCE`; optional discovery override `OIDC_JWKS_URL`. Frontend requires `BACKEND_URL`, `NEXTAUTH_URL`, strong `NEXTAUTH_SECRET`, `OIDC_ISSUER_URL`, `OIDC_CLIENT_ID`, `OIDC_CLIENT_SECRET` and API audience/scopes as described in README. Configure a real OIDC callback `/api/auth/callback/oidc`; no real production provider has been provisioned yet.

From backend: `uv sync --locked`, `uv run alembic upgrade head`, `uv run alembic check`, then `uv run uvicorn app.main:app --host 127.0.0.1 --port 8000 --no-access-log`. From frontend: `npm ci`, `npm run build`, `npm start`. New users have no memberships; use trusted `python -m app.admin` provisioning as documented in README, never automatic email linking or public grants.

Extraction configuration: `FLA_PROCESSING_LIMITS` JSON, `FLA_MAX_EXTRACTION_ATTEMPTS`; upload limit remains `FLA_MAX_UPLOAD_BYTES`. Process and financial-review actions require a UUID Idempotency-Key. All reads require current organization membership; viewers cannot mutate. Financial review/evaluation requires source-backed inputs and current expected revisions. No new direct dependency or runtime environment setting is introduced by Phase 4.

Phase 5 optionally accepts versioned `FLA_PROOF_LIMITS` JSON; defaults are recorded with each issuance. Proof writes require a UUID Idempotency-Key. Owner/admin alone approve disclosure, finalize proof review, export/download JSON artifacts or create explicit successors; analysts may generate, annotate and propose. No PDF dependency, public token, vendor delivery, universal retention duration or automatic erasure exists.

Phase 6 requires PostgreSQL 17 commit-timestamp tracking enabled at server start (`track_commit_timestamp=on`); compose/CI enable it. It uses actual transaction commit provenance for historical known-at K, never insertion time. Post-commit immutable publication metadata is retryable; unavailable provenance is explicitly unresolved/fail-closed. See the architecture/report for the uncaptured-vacuum gap limitation. Optional `FLA_RECOVERY_LIMITS` JSON selects the versioned section-32 operational profile; request and final-action idempotency use UUID headers. Ordinary database application roles must not have DDL/trigger-disabling privileges.

## Known limitations and next step

Extraction still supports explicit labeled templates only; broad free-form contracts, OCR, semantic PDF tables/coordinates, Excel date serials, multilingual normalization and provider calibration are deferred. Synchronous Linux worker and on-request lease recovery are MVP execution, not a durable production queue or security sandbox. Existing real-provider, storage, monitoring/rate-limit and operational security debt remains.

Financial authority relies on explicit human-reviewed source meaning, not autonomous legal interpretation. Review UI supports the common single-line profiles; richer eligible base groups, multiple adjustments and complete rounding-alternative sets use the typed API. Source selectors show the first 100 records with a notice; summaries cover at most 1,000 recent evaluations and disclose the bound. Financial transactions serialize within one organization. Complex period allocations with credits block. No real OIDC-provider browser acceptance or production deployment is claimed. Production database roles must not have DDL/trigger-disabling privileges.

Proof-specific limits: synchronous work and PostgreSQL tenant serialization bound throughput; actual sources must remain available in protected storage. Privileged filesystem/schema interference is detected as integrity loss and is outside normal application-write guarantees. Recognized historical financial/proof version identifiers are pinned; no evaluation-time deployment digest is invented. Manual citations remain reviewer assertions, not machine-verified quotations. PDF bounding boxes/OCR and a production deployment/real-provider browser acceptance remain absent. Explicit disclosure paths are authored through the UI/API; conservative masking can reject a disclosure that cannot safely retain required metadata. Production load testing and compliance/retention policy are separate future work.

Approved V1 scope is internal proof views plus owner/admin canonical JSON download, with distinct nonpositive/blocked evidence packages and separate versioned redacted disclosure views. Technical C01–C10 completeness is automatic; optional owner/admin review, financial currentness/decision and source availability remain separate. PDF/dependencies, external/vendor/public sharing and delivery workflows, aggregate proof/report persistence and automatic legal erasure are out of scope. Retention duration, legal holds, jurisdictional deletion, tenant offboarding and backup erasure need a later explicit compliance/legal policy; no permanent-retention or regulatory-compliance claim is authorized.

PD5-14's initial `proof-operations/1` defaults are engineering safety settings, not financial-policy invariants. Measured performance, production load testing, enterprise usage and infrastructure capacity may support versioned tuning only if it cannot truncate proof, suppress valid amounts, weaken authorization/tenant isolation/integrity, alter calculations or turn incomplete evidence complete. Exceeded bounds return explicit bounded-resource results/errors and preserve financial truth.
